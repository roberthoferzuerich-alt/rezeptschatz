8. SYNCHRONISIERUNG
==================

Behandle die Synchronisierung als ausdrücklich zu entwickelnde Projektfunktion.
Sie entsteht nicht automatisch durch SQLite und Laravel.

Entwirf vor der Implementierung ein verständliches Protokoll.

Das Protokoll muss folgende Situationen behandeln:
- ein neues Rezept wird offline angelegt
- ein Rezept wird offline geändert
- ein Rezept wird offline gelöscht
- ein Rezept wird im Browser geändert
- zwei Geräte ändern dasselbe Rezept
- eine Anfrage wird nach einem Timeout erneut gesendet
- eine Verbindung bricht mitten im Abgleich ab
- Metadaten werden übertragen, aber ein Bild-Upload schlägt fehl
- ein Gerät war längere Zeit offline
- die App wird während der Synchronisierung beendet

Anforderungen:
- stabile UUIDs
- idempotente Verarbeitung wiederholter Schreiboperationen
- eindeutige Kennungen für Synchronisierungsoperationen
- serverseitig geprüfte Versionsnummern
- erkennbare Versionskonflikte
- keine unbemerkte Überschreibung konkurrierender Änderungen
- persistente lokale Outbox
- bestätigte Änderungen erst nach erfolgreicher Verarbeitung aus der Outbox entfernen
- transaktionale Änderungen, wo erforderlich
- definierte Behandlung von Löschungen
- nachvollziehbare Wiederholungsstrategie
- Begrenzung paralleler Synchronisierungsläufe

Verlasse dich nicht allein auf Gerätezeitstempel zur Reihenfolge oder Konflikterkennung.

Bevorzuge für Änderungsabrufe einen serverseitig definierten Cursor oder eine vergleichbar robuste Lösung.
Definiere:
- was der Cursor bedeutet
- wann er lokal gespeichert wird
- wie paginierte Antworten verarbeitet werden
- wie Löschungen übertragen werden
- wie ein vollständiger Neuabgleich funktioniert

Lege fest, ob Zutaten, Schritte und Kategoriezuordnungen gemeinsam mit dem Rezept als Aggregat synchronisiert werden.
Begründe diese Entscheidung.

Für die erste Version ist eine einfache, verständliche Konfliktlösung ausreichend:
- lokale Version behalten
- Serverversion übernehmen
- optional lokale Version als neues Rezept speichern

Eine automatische feldweise Zusammenführung ist zunächst nicht erforderlich.

Verhindere, dass ein alter Offline-Datensatz ein bereits gelöschtes Rezept unabsichtlich wiederherstellt.

Dokumentiere eine Aufbewahrungsstrategie für Löschmarkierungen und Operationskennungen oder lege für die erste Version ausdrücklich fest, dass sie noch nicht automatisch bereinigt werden.

10. Wiederholte Anfrage erzeugt kein doppeltes Rezept.

12. Server aus Backup wiederherstellen und den Wiederanlauf prüfen.
